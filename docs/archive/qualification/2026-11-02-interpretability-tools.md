# Interpretability tools: pretrained encoder qualification

Passed on pretrained GPT-2 and CLIP text encoders, using CPU float32. This
qualifies numerical mechanics and integration for the configurations below.
It does not establish a ground-truth circuit, concept-specific behavior, human
validity, generation quality, GPU support or leaderboard-score parity.

The loader verifies every listed file's size and content hash against a pinned
Hub listing before inference. The [model manifest](../../examples/interpretability_models.json)
retains those identities; weights are not redistributed. The check runs through
the shipped `TextWrapper`, `BrainScoreModel.interact`, `SessionProtocol`,
`load_tool`, `attach_tools` and `TorchInstrumentation`.

The run used Python 3.11.15, PyTorch 2.13.0, transformers 4.57.6, NumPy 1.26.4,
scikit-learn 1.7.2 and concept-erasure 0.2.4 on macOS arm64, with two CPU threads.
The [GPT-2 report](interpretability-tools/gpt2.json) and
[CLIP report](interpretability-tools/clip.json) include environment/source
provenance, the driver checksum, observed errors and hashes of generated files.
The recorded tool implementation revision is the preceding implementation
commit; the driver checksum identifies the qualification code added with these
reports. Full activity arrays and experiment records are generated by the
commands below and retained locally, rather than bundled with the library.

## Checks without causal ground truth

Ground truth is available for the numerical operation even when the model's
true mechanisms are unknown. The reference activity is a native forward on
the same model, input tokens, attention mask, device and dtype. Independent
calculations specify what each intervention must do to that activity.

| Check | GPT-2 | CLIP text |
| --- | --- | --- |
| Native output versus session output | Exact | Exact |
| Recording, call observation and two probes leave activity unchanged | Exact | Exact |
| Selected-unit ablation and scaling; untouched units preserved | Exact | Exact |
| Steering at strengths +0.5, -0.5 and 0 | Exact versus native float32 addition | Exact versus native float32 addition |
| Scaling followed by steering | Exact versus ordered reference | Exact versus ordered reference |
| LEACE live application | Exact versus reference map cast to float32 | Exact versus reference map cast to float32 |
| Exact donor patch with explicitly equal masks and shapes | Exact | Exact |
| Restoration after normal exit and intentional failure | Exact | Exact |
| Save/reload outputs for all three fitted tools | Exact | Exact |
| Probe predictions versus independent sklearn, offline and at all hooked positions | Pass | Pass |
| Parameter/buffer bytes, parameter gradients and PyTorch RNG | Unchanged | Unchanged |
| Hook ownership and public-method restoration | Pass | Pass |
| Persisted records and explicit failure status | Pass | Pass |
| Reasoning recorder | Explicitly unavailable | Explicitly unavailable |

There are nine protocol conditions: baseline, ablation, scaling, positive
steering, negative steering, zero dose, LEACE erasure, scaling plus steering,
and restored baseline. A separate donor-patch scope and intentionally failed
steering scope exercise direct attachment. Two probes and before/after activity
recorders run together in the protocol. Every scope must execute a real forward;
extraction caching is disabled.

Offline transforms calculate in float64 and cast to the input assembly dtype.
Against independent float64 calculations, the largest absolute errors were
`1.342e-5` for GPT-2 LEACE, `9.537e-6` for GPT-2 steering, `2.191e-7` for CLIP
LEACE and `1.491e-7` for CLIP steering. These comparisons use
`atol=2e-5, rtol=2e-5`; they are numerical agreement, not exact equality.
The live/reference and restoration comparisons marked exact above had zero
observed error. Tolerances were declared before the trained runs.

These encoders expose no reasoning trace. This run checks that absence is kept
as absence. Provider-exposed reasoning text, multiple named extractors, streamed
fragments and extraction failures are covered by the offline recorder tests;
there is no claim of recovering hidden reasoning or validating its faithfulness.

## Descriptive probe diagnostics

Fit on 32 explicitly supplied color sentences and evaluate on eight disjoint
sentences with different objects and a different template. Discovery/evaluation
separation is enforced. Labels come from the literal words `red` and `blue`;
they are not human neural measurements. A probe fitted to one fixed permutation
of discovery labels supplies a descriptive shuffled-label control.

| Fixed discovery probe evaluated on | GPT-2 accuracy | CLIP text accuracy |
| --- | --- | --- |
| Original held-out activity | 5/8 | 8/8 |
| LEACE-transformed held-out activity | 4/8 | 5/8 |
| Shuffled-label probe on original held-out activity | 4/8 | 4/8 |

No accuracy threshold is a qualification gate. Eight examples cannot establish
generalization, complete concept erasure or concept-specific causality. A fixed
probe's degradation after erasure also does not show that a newly trained probe
cannot recover information. Behavioral dose-response, retrained probes, nuisance
controls, unrelated tasks and any human comparison belong in a separate
scientific experiment designed for the chosen hypothesis.

## Reproduce

Use a coordinated UMI environment with the test and interpretability extras.
Stage the exact loader files from the model manifest; the qualification itself
uses `local_files_only=True` and downloads nothing. Point the variables below to
those snapshot directories. CLIP uses the verified PyTorch checkpoint and
requires a torch version compatible with the installed transformers loader.

```bash
RESULTCACHING_DISABLE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  python examples/interpretability_qualification.py --model gpt2 \
  --snapshot "$GPT2_SNAPSHOT" --out /tmp/new-gpt2-tool-qualification

RESULTCACHING_DISABLE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  python examples/interpretability_qualification.py --model clip \
  --snapshot "$CLIP_SNAPSHOT" --out /tmp/new-clip-tool-qualification
```

The commands write fitted artifacts, complete experiment records and
`qualification.json`. Existing output directories are refused. A failed check
raises and leaves a failed report; it cannot silently become a skipped test.

The equivalent opt-in trained tests are:

```bash
RESULTCACHING_DISABLE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
UMI_TEST_CPU_ONLY=1 \
UMI_INTERPRETABILITY_GPT2_SNAPSHOT="$GPT2_SNAPSHOT" \
UMI_INTERPRETABILITY_CLIP_SNAPSHOT="$CLIP_SNAPSHOT" \
  python -m pytest tests/test_interpretability_qualification.py -m slow -q
```

Fast tests in that file exercise the same gates on a small fixture and reject
incorrect, nonfinite or mismatched outputs and missing checkpoints. They verify
disjoint discovery/evaluation data. They run in the normal offline suite; they
do not substitute a fixture for either trained-model result above.

Validation for this change: seven fast qualification tests and two trained-model
tests passed. The full offline unified unit/integration suite passed with
1,772 passed, 48 skipped and 65 deselected; the latter includes the opt-in
trained tests, which were executed separately.
