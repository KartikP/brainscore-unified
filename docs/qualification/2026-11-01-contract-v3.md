# Contract v3: implementation and checks

This change aligns session matching and routing across core, vision, language
and unified. Scientific benchmark formulas and legacy model plugins are unchanged.

## What changed

| Area | Behavior |
| --- | --- |
| Compatibility | Match declared inputs and outputs. Full and partial matches run; incompatible pairs fail before scoring. Scores record the consumed/dropped inputs. |
| Session inputs | Buffered sessions validate all supplied inputs before execution. Input views hide unsupported streams; live observations are validated when they become available. |
| Channel registration | Duplicate family registration requires explicit replacement. Entries can declare concrete payload types. Experiments reject unregistered channels. |
| Model assembly | Stock session handlers and external capabilities use the same registry. Unwired neural, behavioral and motor paths are not advertised. |
| Extraction | Canonical extractor mappings use one call shape, without signature inspection. Input preparation stays in the extractor. |
| Legacy benchmarks | Domain loaders select the permanent facade for legacy APIs. It translates trial count, time bins, task and recording settings into sessions. |
| Legacy language | The adapter supports behavioral requests and joint neural/behavioral responses without repeating the original digest call. |
| Replay | Saved typed environment observations use an explicit compatibility source. Their payloads and timestamps are preserved. |
| Teaching material | The contract guide explains matching and compatibility paths. Notebook 18 presents raw image pixels and prepares tensors inside its subject. |

## What the tests establish

The tests cover declaration matching without inference, full/partial score
metadata, malformed buffered inputs, duplicate registration, handler selection,
extractor calls without signature inspection, ignored input streams, and saved
observation replay. Legacy fidelity checks compare returned arrays and settings
against the direct legacy boundary: visual field, trial counts, time bins,
recording type, behavioral tasks and joint language outputs.

The notebook adapter is exercised with a tiny local network. The notebook was
not re-executed with downloaded ResNet weights as part of this change.

The coordinated offline suite includes legacy adapters, numerical helpers,
cache checks, extraction, experiment lifecycle, recording/replay, environment
sessions, and loopback OpenPI transport checks. It is broader than the new tests.

## Compatibility boundaries

- Deprecated extractor constructor forms still use a separate adapter for their
  historical signatures. Canonical mappings do not enter that adapter.
- Existing typed environment sessions and recordings keep their EnvironmentStep
  boundary. New buffered observations use StreamEvent envelopes. This avoids
  silently rewriting saved scientific evidence.
- Private state aliases and old model method spellings remain forwarding
  compatibility code; internal model components access their owned state directly.
- Domain benchmark variants using the retained typed API declare that route
  explicitly. This change does not rewrite their scientific evaluation procedure.
- A custom subject must honor the measurement settings delivered in its session.
  Carrying time bins or trial counts does not prove an arbitrary external subject
  implements them correctly.

## Qualification limits

This is source-based offline qualification in an existing Python environment,
with result caching and model downloads disabled. It is not a fresh installation,
trained-model GPU qualification, or a rerun of the production score matrix.
No new scientific tolerance is introduced. Existing score parity remains a
release requirement on pinned packages and data.

This PR addresses the migration above; it does not certify every third-party
subject or every rule in the v3 specification. In particular, external response
provenance and custom payload validators remain the integration author's
responsibility. Live future observations cannot be validated before they exist.

## Reproduce

Use the coordinated peer revisions and run from the parent of the four checkouts:

```sh
RESULTCACHING_DISABLE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  python -m brainscore.validation.workspace \
  --root . --out contract-v3-checks.json
```

Run without AWS credentials. The report lists selected tests and accounts for
optional skips; it does not treat unselected plugin suites as passing.
